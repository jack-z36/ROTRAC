# 扭转功能层（DexTwist）算法与验收基线

> 新会话为何需要本文：扭转层是叠加在逐指 IK 基线之上的第二条控制路径，包含门控、累积转角、六关节残差精修、独立有效性门和独立诊断录制。这些语义无法从消息字段或测试名单独读出；调参、回退排查和换手复用前必须先读本文。

本文描述 `hand_retargeting` 第一版扭转功能层。它不改变自由空间逐指 IK、`RetargetingState`、O10 控制节点安全语义和采数据 MCAP；只新增扭转门控、人手螺旋轴与累积转角、机器人三指参考、四项目标、解析梯度投影精修、回退门和诊断链路。

本文是算法与验收口径；字段清单和枚举数值以 `src/teleoperation_support/ros_interfaces/msg/TwistState.msg` 为准，接口语义见《Rokoko输入与重定向状态接口语义》，上层决策见 ADR-0021/0022/0023。

## 1. 数据流与作用范围

```text
Rokoko raw_hand
  -> 归一化与人体掌坐标
  -> baseline 五指 IK（既有路径）
  -> 三指捏合门控与参考锁存（门控在 baseline 之前更新）
  -> 6 个 tripod 主动关节残差精修（baseline 提交之后、低通之前）
  -> 10 维软目标
  -> 既有低通滤波
  -> /o10_control/{side}/command
  -> O10 控制节点硬限速
  -> /o10/{side}/joint_cmd
```

- 扭转层是叠加层。门控未激活时，10 维组合与发布路径完全走既有基线，仅无名指/小指事件不被改写。
- 精修变量固定为 6 个 tripod 主动关节：`thumb_roll, thumb_abad, thumb_mcp, index_abad, index_pip, middle_pip`。无名指、小指始终走基线。
- 每帧精修从本帧基线 IK 结果初始化，不使用上一帧精修结果 warm start；不写基线最近有效目标、`has_valid_ik` 或下一帧 warm start。
- 精修失败时本帧发布基线命令，并通过 `TwistState` 报告失败原因。
- 不控制机械臂或腕部；不新增操作者控制；`clear_fault` 仍是唯一操作者控制操作。

## 2. 三指捏合门控

三指为拇指、食指、中指指尖，表达在人体解剖学手掌坐标系。尺度为该侧三指运行期冻结指链长度的平均值。两何量都归一化后与阈值比较：

- 孔径：三指尖两两距离的最大值除以尺度。
- 伸展：三指尖中心到掌心原点的距离除以尺度。
- 进入：`aperture < gate_aperture_on` 且 `extension > gate_extension_min`，连续 `gate_on_frames` 帧。
- 退出：`aperture > gate_aperture_off` 或 `extension < gate_extension_min`，连续 `gate_off_frames` 帧。
- 配置层强制 `gate_aperture_off > gate_aperture_on`，形成迟滞。
- 当前帧掌坐标无效或三指任一目标无效时，门控计数和状态都不更新，保持上一状态。
- 门控是逐侧状态；左右手互不影响。
- 门控不引入 Service、按键或模式开关；构建通过后默认开启，门控是唯一运行时条件。

`extension` 下限用于排除握拳等低位三指姿态；孔径上限用于排除张开手。门控只看人手几何，不看机器人反馈。

## 3. 人手意图与累积转角

- 螺旋轴：`unit((p_index - p_thumb) × (p_middle - p_thumb))`，符号对齐人体掌系 `+Z`。
- 激活时锁存轴 `a_task`，并锁存两条平面内单位向量：拇指→食指、拇指→中指在垂直于 `a_task` 平面上的投影。
- 每帧增量：两条平面内向量绕 `a_task` 的有符号转角取平均；增量裁剪到 `±delta_theta_clip`。
- `theta_task` 只在门控激活且几何有效时累加；跨 re-grasp 保留。
- 每次激活记录 `theta_base = theta_task`；本次目标增量 = `theta_task - theta_base`。这样松开再捏不会把已经转过的角度再执行一遍。
- 退出只停止累加，不重置 `theta_task`。
- 轴或平面内投影退化时，本帧不累加、不精修，报告`human-geometry-invalid`；激活时退化报告`human-reference-invalid`。
- 激活时把人手轴映射到机器人掌系，与机器人参考轴比较；反向或正交（点积 ≤ `1e-6`）时不进入精修，报告`axis-mismatch`，不翻转累积角。该检查在真实左右手资产上已核对为同向（点积约 0.99）。
- 激活帧人手几何瞬时退化不会锁死整个 episode：门控保持激活时，只要三指几何恢复有效就重试轴锁存；机器人参考的瞬时 `robot-reference-invalid` 也逐帧重试。`axis-mismatch` 是持续符号约定失败，不重试。
- stale 时重置门控、机器人参考和反馈诊断，但保留 `theta_task`；恢复后门控必须重新满足进入条件，`theta_base` 在下一次激活时重新记录。

## 4. 机器人三指参考与目标函数

机器人三指工具坐标系同样由三指尖构造，表达在规范 O10 掌系。激活帧从 baseline 关节角锁存：

- 参考轴 `a_r_ref`，符号对齐机器人掌系 `+Z`；
- 参考 closure `e_r_ref`：三个指尖两两距离组成的 3 维向量；
- 参考 centroid `c_r_ref`：三指中心；
- 两条平面内参考向量（与人体侧同法构造）。

`theta_r(q)` 用与人体侧相同的两条平面内向量平均法，绕 `a_r_ref` 计算。轴偏差为当前三指法向与 `a_r_ref` 的夹角；当前法向先对齐参考轴符号。

目标函数：

```text
J(q) = w_rot  * (theta_r(q) - (theta_task - theta_base))^2
     + w_conn * ||e_r(q) - e_r_ref||^2
     + w_axis * (1 - (a_r(q) . a_r_ref)^2)
     + w_pos  * ||c_r(q) - c_r_ref||^2
```

- closure 和 centroid 两个距离项用三指平均机器人指链长度归一化；`rot` 和 `axis` 无量纲。
- 四权重由配置显式给出，不在代码中隐藏默认值。
- `e_r` 和 `c_r` 从候选关节经耦合和完整 FK 计算。
- 目标项分别写入 `TwistState.objective_rot/conn/axis/pos`，总值为四项之和；不可用时为 NaN。

## 5. 优化器与解析梯度

- 变量：6 个 tripod 主动关节，带 `JOINT_LIMITS` 上下界。
- 初值：本帧 baseline IK 结果。
- 迭代次数固定为 `twist_iterations`（首版 5）。
- 方向：负梯度按无穷范数归一化。
- 步长：每次迭代每关节不超过 `step_max`，并裁剪到关节限位和以 baseline 为中心的 trust region。
- 回溯：候选目标值没有严格下降时步长减半，最多两次减半。
- 提前停止：梯度无穷范数不超过 `gradient_tolerance`。
- 运行时禁止数值差分；梯度必须解析计算。
- 解析梯度来源：Pinocchio 一次 FK 给出三个 tip 的位置和完整 3×16 平移雅可比；耦合模型给出 16×6 主动—被动耦合雅可比；closure、centroid、法向、轴偏差和平均转角的链式法则。
- 解析梯度在离线测试中用中心差分独立验证，覆盖左右手、多个可行域内部状态和接近限位但扰动后仍合法的状态。

## 6. 有效性、回退与失败原因

baseline 逐指 IK 继续走现有残差门，决定本帧能否进入扭转。精修结果使用独立门：

- 所有候选关节有限；
- 在关节限位内；
- 相对 baseline 的总变化在 trust region 内；
- 三指几何非退化：法向模长和平面内投影模长大于配置阈值；
- 当前三指法向与参考轴夹角不超过 `axis_deviation_limit_deg`；
- 目标函数有限。

任一门失败：本帧发布 baseline 命令，`refinement_status=FALLBACK_BASELINE`，并写入失败原因。`TwistState.failure_reason` 枚举覆盖：参考无效、人体参考无效、人体几何无效、后端不可用、求解器异常、非有限、限位、trust region、几何退化、轴偏差超限、baseline 不完整、精修被拒、轴反向。

额外回退条件：

- baseline 不完整（任一手指没有提交值）时不精修，报告`baseline-incomplete`；
- 模型资产或数值后端不可用时回退并报告`backend-unavailable`，不伪造成功；
- 门控激活期间跳过 `_apply_thumb_adjustments` 对 6 个 tripod 关节的处理（固定值和增益都不应用）；退出后恢复；
- 精修结果仍经过既有低通和 O10 控制节点硬限速；扭转层不能绕过安全边界；
- O10 反馈只读，不参与门控、精修、回退或发布决策。

## 7. 诊断、录制、回放与验收

### 7.1 `TwistState`

`/hand_retargeting/{side}/twist_state`，消息 `rokoko_omnihand_msgs/msg/TwistState`。字段覆盖门控、角度、轴偏差、四项目标、状态、迭代/评估/耗时和帧有效性。不可用字段用可用位 `false` + NaN；`theta_robot_cmd` 从本帧发布命令对应关节角计算，回退时等于 baseline 测量值；`theta_robot_fb` 从最新 O10 反馈计算；反馈缺失、参考无效或几何无效时不可用。详细语义见接口文档。

发布时机：每帧 raw hand、stale 进入时发布；模型资产不可用时发布 `valid=false`、`failure_reason=BACKEND_UNAVAILABLE` 的显式不可用快照。诊断 topic 是只读观测，不参与控制。

### 7.2 独立录制

规范入口 `./scripts/start_omnihand_control.sh` 在业务节点之前启动 `scripts/record_twist_diagnosis.sh`，输出 `runs/twist-diag/<timestamp>/`：`bag/`、配置快照、git commit、topic 列表、README、QoS override、metadata。七类 topic 逐侧录制；best-effort QoS override；磁盘和时长保护；Ctrl-C/TERM 时 rosbag2 收到 SIGTERM 并正常关闭 MCAP。该录制与采数据 MCAP 完全分开，业务节点不写 MCAP。`--dry-run` 只打印路径和完整命令。

### 7.3 分析与回放

- `scripts/analyze_twist_diagnosis.py`：从 MCAP 读取 `TwistState`，输出 `summary_<side>.json` 和 `frames_<side>.csv`。指标包括 `theta_robot_fb - theta_increment` 的 RMSE/MAE/Pearson、命令侧同项、反馈轴偏差均值/最大值、精修应用/回退比例、失败原因分布和负样本门控误触发率。时间对齐用消息 `header.stamp`；负样本窗口是相对该侧首条 `TwistState` 的时间。
- `scripts/replay_twist_diagnosis.py`：把录制的 `raw_hand` 离线喂给生产 `RetargetingSession`（同一配置快照和 Pinocchio/NLopt 后端），按 stamp 对齐命令、按序列对齐 `TwistState`，输出差异 JSON。
- 第一版只验收机器人侧：转角和轴偏差。**物体实际转角未测**；没有物体位姿/ArUco/滑移测量，不得把“机器人转角跟上了”写成“物体拧成功了”。

### 7.4 验收清单

- 转角反馈：RMSE、MAE、Pearson（反馈可用帧）；
- 轴偏差反馈：均值、最大值；
- 精修应用/回退比例与失败原因分布；
- 负样本会话中的门控误触发率（激活帧/有效门控帧，及激活 episode 数）；
- 自由空间回归：现有五指 IK/状态测试与真实数据回归保持通过；
- 真机试点：1 名操作者、左手、1 个物体、3 次扭转 × 10 秒；另录 2 分钟自由空间和普通抓握负样本；试点通过后扩到 3 种物体 × 5 次。

## 9. 与论文的差异

以下差异是有意为之：

- 不控制机械臂；扭转只在掌心坐标系内完成。
- 人手和机器人转角用两条平面内向量的平均有符号角，而不是完整工具坐标系的 log map；每帧小角度下等价，且更抗单指噪声。
- 运行时用解析梯度和固定迭代次数，而不是论文的中心差分梯度。
- 目标距离项按机器人指链长度归一化；论文未规定归一化，本版选择无量纲化以便调参和换手。
- re-grasp 时使用 `theta_task - theta_base` 作为本次目标，避免机器人重复已完成的转角。
- 反馈转角只用于诊断，控制不闭环到硬件反馈。

## 10. 已知限制

- O10 tripod 只有 6 个主动关节，扭转能力受机械结构限制；精修可能频繁碰限位。
- 物体实际转角、滑移和接触力不可测；第一版只能验收机器人转角 vs 人手意图和轴偏差。
- 四个权重、门控阈值、步长、trust region、`delta_theta_clip` 都未标定；首版值只用于试点。
- 扭转期间忽略拇指固定值和增益；依赖这些补偿的操作者会发现扭转期间手型不同，退出后恢复。
- 扭转层构建通过后默认开启；门控误触发会直接改写命令，试点必须在安全台架上进行。
- 第一版真机只采左手；右手 wire 已通，但未做真机验收。
- 杆端 `scripts/init_omnihand.sh` 全量自检仍有 5 项既有 `test_t10_faults` 失败（故障注入时序，单独运行同样失败，与扭转层无关）；构建、消息生成、扭转核心/会话/wire 测试全绿。
