# Rokoko 到 OmniHand O10 全流程启动手册

> 新会话为何需要本文：真机启动是硬件安全操作。本文保留启动顺序、每一步"为什么"、安全红线和常见现象判读；命令参数以脚本与 launch 为准，本文不复述可直接从 `--ros-args` 读出的全部默认值。
>
> 2026-10 蒸馏自旧《全流程启动手册》：规范入口与路径已按扁平化后仓库结构更新（根入口在 `scripts/` 下，数值环境默认 `.venv`，模型资产在仓库根 `omnihand_o10_model/`）。

本文面向第一次运行系统的操作者，说明如何启动并检查完整链路：

```text
Rokoko Studio
    ↓ UDP 14043
rokoko_hand_receiver
    ↓ /rokoko/{side}/raw_hand
hand_retargeting
    ↓ /o10_control/{side}/command
omnihand_o10_hardware_provider
    ↓ /o10/{side}/joint_cmd
OmniHand O10
```

## 重要安全说明

> **当前实现（`4fedfaa` 起）已移除 `arm`/`disarm`，运动由新鲜合法软目标直接驱动。** 只要反馈就绪、错误监控就绪、目标就绪且目标新鲜，`motion_enabled` 即为 true，重定向节点发布的每条新目标都会驱动实体手产生命令；停止发布新目标（或目标 2 秒内不更新）即自动暂停。因此：

- 启动完整真机链后，**只要戴着手套并移动手，实体手就会跟着动**。开始前必须确认实体手周围无遮挡、人员与设备安全。
- 不要同时点亮合成输入源与真机 provider：合成假帧喂进真机链会直接驱动实体手。
- 手动中断运动：停止向 `/o10_control/{side}/command` 发布（收起手套、移出 Rokoko 有效区或停掉重定向节点）；若发生 `fault_latched`，先检查 `hardware_error_bits`，确认致命错误位（bit0–bit3）清零后调用 `clear_fault`（`commu_except`/bit4 是历史通信标记，不阻止清除）。
- 操作者唯一的操作 Service 是每侧 `/o10_control/{side}/clear_fault`；不存在 `arm`/`disarm` Service。

状态观察重点（控制节点启动并读取反馈后）：

```text
feedback_ready: true
error_monitor_ready: true
target_ready: true
target_fresh: true   # 目标新鲜才允许运动
fault_latched: false
motion_enabled: true  # 上三项就绪且目标新鲜时为 true
```

当前 Provider 会同时初始化左右两侧。如果只有左手实体手接入，右手可能因无反馈而不能完成初始化；只要 Provider 进程仍在运行、左手状态满足安全条件，可继续单独观察左手，**不要用错误的右手参数绕过限制**。

环境与设备前置检查（`.venv` 数值栈、USB VID:PID `a8fa:8598`、`init_omnihand.sh` 验证阶梯）见《运行环境与真机前置条件》；首次真机操作前必须先通过该自检。

## 方式 A：推荐的一键启动

### 终端 0：停止旧进程

```bash
cd "$(git rev-parse --show-toplevel)"
source /opt/ros/jazzy/setup.bash
source "$(git rev-parse --show-toplevel)/scripts/workspace_paths.sh"
source "$ROTRAC_INSTALL_BASE/setup.bash"
ros2 node list
```

如果看到以下任意节点，请回到启动它们的终端按 `Ctrl+C`：

```text
/rokoko_hand_receiver
/hand_retargeting
/omnihand_o10_hardware_provider
/o10_control_node
```

### 终端 1：一键启动整条链路

```bash
cd "$(git rev-parse --show-toplevel)"
./scripts/init_omnihand.sh          # 先自检（见 AGENTS.md 开工自检要求）
./scripts/start_omnihand_control.sh # 唯一规范入口；实现位于 bringup 包
```

脚本会依次启动接收节点、重定向节点、HCAN Provider 和 O10 控制节点；日志写入 `/tmp/omnihand-control-<timestamp>/`。保持终端 1 运行，按 `Ctrl+C` 会停止本次脚本启动的子节点。脚本不调用任何操作 Service（不调用 `clear_fault`）。它默认使用 `<仓库根>/.venv` 作为数值环境、`<仓库根>/omnihand_o10_model` 作为模型资产（可用 `DEXHIT_COLLECTION_PREFIX` / `OMNIHAND_O10_MODEL_FIXTURE` 覆盖）。

右手单侧调试可使用仓库根快捷入口；它保留已验证的右手参数组，并在控制节点就绪后自动请求 30 Hz 触觉流：

```bash
./scripts/start_omnihand_right_low_latency.sh
```

等价的通用启动器选项是 `--sides right --tactile-rate 30`。30 Hz 是请求频率；实际发布频率受 SDK 请求间隔、HCAN 带宽以及关节控制流量限制，启动后用 `ros2 topic hz /o10/right/tactile_states` 实测。触觉与控制共用 SDK 通信锁，若控制频率或反馈新鲜度下降，应降低触觉频率。

## 仅测试左手：推荐操作顺序

如果只有左手实体手接入，目标又是"只让左手参与本次测试"：

1. 仍然启动完整节点图——当前 Provider 会同时创建左右两个侧别，没有真正的 Provider `left_only` 模式；
2. 只观察左手 Topic 和左手状态，不要刻意初始化右手；
3. 运动由目标直接驱动：只要左手反馈就绪且目标新鲜，左手运动即自动开启；安全确认后戴上手套即可测试，无需任何 arm；
4. 右手出现 `read_active_joints returned 0 positions` 说明右手没有反馈，不要用错误参数伪造右手；只要 Provider 仍在运行且左手状态满足安全条件，可继续单独观察左手。

启动一键脚本后，在新终端只检查左手：

```bash
source /opt/ros/jazzy/setup.bash
source "$(git rev-parse --show-toplevel)/scripts/workspace_paths.sh"
source "$ROTRAC_INSTALL_BASE/setup.bash"

ros2 topic hz /rokoko/left/raw_hand        # 约 30 Hz
ros2 topic hz /o10_control/left/command    # 约 30 Hz
ros2 service call /o10/left/read_active_joints rokoko_omnihand_msgs/srv/ReadO10ActiveJoints '{}'
# 必须看到 success=True result_code=0，并返回 10 个位置
ros2 topic echo /o10_control/left/state
```

确认实体手周围安全、状态满足下方条件后，才戴上手套开始左手动作测试（满足即自动运动，无需 arm）：

```text
feedback_ready: true
error_monitor_ready: true
target_ready: true
target_fresh: true
fault_latched: false
motion_enabled: true
```

动作测试期间继续观察 `/o10_control/left/state`。若看到 `fault_latched: true`、致命错误位（bit0–bit3）非零或实体手动作异常：先停止移动手套/收起手，检查硬件错误位，确认产生原因并解决后再调用左手 `clear_fault`：

```bash
ros2 service call /o10_control/left/clear_fault rokoko_omnihand_msgs/srv/ControlOperation '{}'
```

确认实体手周围安全后再戴手套恢复测试。停止时按 `Ctrl+C` 关闭启动终端即可（本轮不再需要任何 disarm）。

## 方式 B：手动分终端启动

手动方式使用 6 个终端。每个持续运行的节点终端都不要关闭。

### 终端 0：公共环境准备

每个新终端先执行：

```bash
export COLLECTION_ROOT="$(git rev-parse --show-toplevel)"
source /opt/ros/jazzy/setup.bash
source "$COLLECTION_ROOT/scripts/workspace_paths.sh"
source "$ROTRAC_INSTALL_BASE/setup.bash"
```

### 终端 1：Rokoko 接收节点

```bash
cd "$(git rev-parse --show-toplevel)"
source /opt/ros/jazzy/setup.bash
source "$(git rev-parse --show-toplevel)/scripts/workspace_paths.sh"
source "$ROTRAC_INSTALL_BASE/setup.bash"

ros2 run rokoko_hand_receiver rokoko_hand_receiver_node --ros-args \
  -p bind_address:=0.0.0.0 \
  -p udp_port:=14043 \
  -p actor_index:=0
```

### 终端 2：手部重定向节点

**不要**用 `ros2 run hand_retargeting hand_retargeting_node`——Pinocchio/NLopt 在 `.venv` 数值环境里，不在 ROS Python 路径中；必须走项目 wrapper（它会 fail-closed 校验环境与模型资产）：

```bash
cd "$(git rev-parse --show-toplevel)"
source /opt/ros/jazzy/setup.bash
source "$(git rev-parse --show-toplevel)/scripts/workspace_paths.sh"
source "$ROTRAC_INSTALL_BASE/setup.bash"

export DEXHIT_COLLECTION_PREFIX="$(git rev-parse --show-toplevel)/.venv"
export OMNIHAND_O10_MODEL_FIXTURE="$(git rev-parse --show-toplevel)/omnihand_o10_model"

bash src/hand_retargeting_node/scripts/hand_retargeting_node \
  --ros-args \
  --params-file runs/retargeting_diag_params.yaml \
  -p recovery_confirmation_timeout_sec:=0.5
```

### 终端 3：HCAN O10 Provider

先确认设备：

```bash
lsusb -d a8fa:8598
```

然后启动（数值库同样来自 `.venv`）：

```bash

source "$(git rev-parse --show-toplevel)/scripts/workspace_paths.sh"
source "$ROTRAC_INSTALL_BASE/setup.bash"

export DEXHIT_COLLECTION_PREFIX="$(git rev-parse --show-toplevel)/.venv"

ros2 run omnihand_o10_hardware_adapter omnihand_o10_hardware_provider \
  --ros-args \
  -p o10.left.transport:=hcan \
  -p o10.left.hand_device_id:=1 \
  -p o10.left.canfd_device_id:=1 \
  -p o10.left.canfd_channel_id:=0 \
  -p o10.right.transport:=hcan \
  -p o10.right.hand_device_id:=1 \
  -p o10.right.canfd_device_id:=0 \
  -p o10.right.canfd_channel_id:=0
```

成功日志应包含：

```text

Device 1, channel 0 opened successfully
Receive thread started
```

### 终端 5：检查整条 ROS 链

```bash
ros2 node list
ros2 topic hz /rokoko/left/raw_hand
ros2 topic hz /o10_control/left/command
ros2 topic info -v /o10_control/left/command
ros2 topic echo /o10_control/left/state
```

应至少看到四个节点：`/rokoko_hand_receiver`、`/hand_retargeting`、`/omnihand_o10_hardware_provider`、`/o10_control_node`。正常状态重点是终端标题"状态观察重点"的六项布尔值。

检查左手只读反馈：

```bash
ros2 service call /o10/left/read_active_joints rokoko_omnihand_msgs/srv/ReadO10ActiveJoints '{}'
# 成功：success=True、result_code=0，返回 10 个位置
```

### 终端 5A：按需开启触觉观测

触觉流默认关闭，不影响控制使能。需要观察触觉时显式设置上报频率：

```bash
source /opt/ros/jazzy/setup.bash
source "$(git rev-parse --show-toplevel)/scripts/workspace_paths.sh"
source "$ROTRAC_INSTALL_BASE/setup.bash"

ros2 topic pub --once /o10/left/tactile_cmd std_msgs/msg/Float32 '{data: 10.0}'
ros2 topic echo /o10/left/tactile_states
# 停止：'{data: 0.0}'
```

`tactile_states` 类型为 `sensor_msgs/msg/Image`，固定 1×268、小端 `mono16`、`step=536`；268 像素按 `thumb/index/middle/ring/little/palm/dorsum` 顺序平铺，区域起始索引 `0/16/34/52/70/88/166`，每两字节一个小端 uint16 触觉值（原始 uint8 数值不变，约 1 g/点）。

触觉与同侧关节命令、反馈和错误查询**共用 SDK 通信锁**；真机尚未标定触觉轮询对遥操作延迟的影响，动作测试期间先用 10 Hz，并同时观察 `/o10/left/joint_cmd` 频率。触觉消息停止或缺失**不等同于控制故障**，不要据此清除故障或改控制参数。

### 终端 6：故障清除

`4fedfaa` 起不存在 `arm`/`disarm`；运动由新鲜目标直接驱动，无需授权。若终端 5 看到 `fault_latched: true` 且致命错误位（bit0–bit3）已清零、通信健康、确认实体手周围安全，可对该侧清除锁存故障：

```bash
ros2 service call /o10_control/left/clear_fault rokoko_omnihand_msgs/srv/ControlOperation '{}'
```

成功应看到 `success=True`。清除后运动**不会立即恢复**——下一条新鲜合法软目标到达时才自动恢复。若致命错误位仍非零，先解决硬件原因，不要盲目清除（完整语义见《O10控制契约与安全语义》第 7 节）。

## 停止流程

手动中断实体手运动：停止发布新鲜目标即可（收起手套、移出 Rokoko 有效区，或停掉重定向/控制节点）；节点停止即自动停止产生命令。

一键启动时回到终端 1 按 `Ctrl+C`。手动启动时依次在对应终端按 `Ctrl+C`：

```text
终端 4：o10_control_node
终端 3：omnihand_o10_hardware_provider
终端 2：hand_retargeting
终端 1：rokoko_hand_receiver
```

不需要也无 `disarm` 调用。

## 常见现象

| 现象 | 处理 |
| --- | --- |
| `/rokoko/left/raw_hand` 没有频率 | 检查 Rokoko Studio IP、UDP 端口 14043 和 Actor |
| 接收节点日志持续 `configured actor does not exist (Rokoko scene has no actor)` | Rokoko 场景里**根本没有角色**：数据到了 UDP 14043 但包内 `actors` 为空，软件无数据可解。到 Rokoko Studio 确认手套已配对/校准且场景里能看到手模型，再启动 |
| 接收节点日志 `actor_index=… out of range; auto-using actor index 0` | 已自动容错：场景里有角色，接收节点自动改用 0 号继续收发，**不会**丢帧；若数据属于另一角色，把 `actor_index` 改成该角色序号 |
| `/o10_control/left/command` 没有频率 | 查看 `/hand_retargeting/left/state` 的 `phase`、`ready` 和 `ik_state` |
| `/o10_control/left/command` 有频率但实体手不动 | 先看 Provider 日志的拒收理由，再怀疑下层：`command name must use the fixed O10 active-joint order` 表示命令 `name` 不符合固定 10 主动关节顺序，被整条拒收（复盘实证：`name` 为空时手纹丝不动，与硬件无关）；同时确认 `/o10/{side}/joint_cmd` 在发（源自 O10 调试复盘《06_归因_手不动根源_命令缺name》） |
| `feedback_ready` 一直 false | 先确认数据源在产生数据：`ros2 topic hz /o10/{side}/joint_states`——源头从不发布时，等待方逻辑再正确也等不到（复盘实证：Provider 曾缺周期发布反馈的职责，属架构缺口而非逻辑错）；源在发再查 `read_active_joints` 与控制侧判定（源自 O10 调试复盘《07_归因_反馈假是control逻辑错》《08_归因_反馈假根源_provider不发布》） |
| `No module named pinocchio` | 使用终端 2 的源码 wrapper，不要 `ros2 run hand_retargeting ...`；确认 `DEXHIT_COLLECTION_PREFIX` 指向含 Pinocchio 的环境（默认 `.venv`） |
| `BLOCKED_ENV: ...` | wrapper fail-closed：`DEXHIT_COLLECTION_PREFIX`/`OMNIHAND_O10_MODEL_FIXTURE` 未设或资产缺 `provenance.json`；按终端 2 的导出补齐 |
| `Failed to open device` | 检查 HCAN 权限、USB-CANFD、供电和设备占用 |
| `fault_latched: true` | 查看 `hardware_error_bits`；确认致命位（bit0–bit3）清零与通信健康后调用 `clear_fault` |
| `commu_except` 或错误位数值 `16` | 厂商历史通信标记（bit4），不锁存故障、不阻止控制；位置/温度/电流等物理量仍可读即说明通信链路是通的，不要据名字判定通信坏了（源自 O10 调试复盘《01_归因_错误字16是通信坏了吗》）；仍应检查 O10 电源、CAN 线、通道和设备状态 |
| `/o10/right/joint_error_cmd` 出现 `{}` | 正常的空错误查询请求 |
| `read_active_joints returned 0 positions` | 对应侧没有读到 10 个关节反馈（当前常见于仅左手接入时的右手） |
| read 服务报 `value … below/above limit …` 超限 | 对该关节连续采样（复盘用 8 次）判稳：读数稳定 ⇒ 数据干净，是限位标准与机械零位失配（LEFT `pinky_abad` 实证：真实零位 -0.1861 低于配置下限 -0.1850，且当前 `omnihand_o10_contracts` 仍为理论限位，见《O10控制契约与安全语义》第 2 节）；读数跳变才怀疑传感器或毛刺（源自 O10 调试复盘《09_归因_超限是读数异常》《10_归因_超限根源_机械零位出界》） |
| `/o10/left/tactile_states` 没有消息 | 先向 `/o10/left/tactile_cmd` 发布正频率；仍无消息时查看 Provider 日志中的触觉完整帧校验或 SDK 读取错误 |
