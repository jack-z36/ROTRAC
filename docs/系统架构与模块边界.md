# 系统架构与模块边界

## 1. 项目定位与主链

项目第一版范围是一条可追踪的机器人数据到部署主链：

```text
collection → raw MCAP → processing → LeRobotDataset v3 → training → ACT bundle → deployment
```

- `raw MCAP` 是 collection 的原始记录边界，保留采集事实，不能被后续处理覆盖；
- `LeRobotDataset v3` 是 processing 对训练数据的规范化交付边界；
- `ACT bundle` 是 training 面向 deployment 的模型交付边界。

跨阶段边界原则：上游拥有输出产物的生成责任，下游不得静默改写上游原始产物；每次交付应能指出输入/输出/验证结果；缓存、日志、数据集、模型是生成物，不混入源码或文档；deployment 依赖交付格式但不把训练细节带入运行时接口。

**本仓库当前实现的是 collection 阶段的 Rokoko → OmniHand O10 实时遥操作链**（ROS 2 Jazzy，仓库根即 colcon workspace）。

## 2. 运行时数据流与职责所有权

```text
Rokoko Studio / Smartgloves ──JSON v3 / UDP 14043──▶ rokoko_hand_receiver
    ──/rokoko/{side}/raw_hand──▶ hand_retargeting
    ──/o10_control/{side}/command──▶ omnihand_o10_control
    ──O10HardwarePort──▶ omnihand_o10_hardware_provider ──Agilink SDK / HCAN──▶ 实体 O10
```

外部 rosbag2/MCAP 观察记录 Raw、重定向状态、软目标、控制状态、最终命令与反馈；**三个业务节点均不直接写 MCAP**。Launchpad（`rokoko_omnihand_launchpad`，本机 `127.0.0.1:8710`）是控制面与设备编排层，不是业务节点，不侵入业务节点内部状态机。无真机自动化验收用相同前三个业务节点 + 纯软件 Provider（`software_o10_provider`，不加载厂商库、不接触设备，只允许出现在测试 composition）。

| 运行模块 | Owns | Must not |
| --- | --- | --- |
| rokoko_hand_receiver | UDP 接入、JSON v3 校验、Actor 选择、21 节点按名重排、Raw 发布与接收统计 | 解释 O10 关节、执行归一化、复用坏侧历史、写 MCAP |
| hand_retargeting | 运行期人体尺度、掌坐标、方向映射、指尖目标、耦合、单指 IK、历史保持、软平滑、stale 恢复、重定向状态 | 锁存故障、厂商 SDK、最终硬件命令、写 MCAP |
| omnihand_o10_control | 软目标复核、逐侧控制状态、运动许可、锁存故障、反馈初始化硬限速、clear_fault、最终命令效果 | 解释人体动作、订阅 RetargetingState 驱动安全门、导入厂商 SDK、写 MCAP |
| omnihand_o10_hardware_provider | O10HardwarePort → 厂商 SDK/设备、逻辑手侧绑定、O10TactilePort 触觉观测 | 解释 Rokoko、运行 IK、拥有使能或安全状态机 |
| 纯软件 Provider（测试） | 同一 O10HardwarePort 的确定性模拟（反馈/错误/超时/重启/断连） | 出现在生产依赖、加载厂商库、接触真实设备 |

## 3. 分层与依赖规则

自有运行时代码沿"知道 ROS/外部框架最多 → 纯业务语义"向内分层，**依赖只允许向内**：

```text
Composition / External（launch、厂商 SDK、rosbag2、运行环境）
        ↓
ROS Runtime & Adapters（Node 生命周期、QoS、参数、消息↔值对象、UDP/时钟、Pinocchio/NLopt/资产）
        ↓
Application / Orchestration（每侧会话状态、阶段转换、IK 调度、stale 恢复候选区、事件→效果原子转换）
        ↓
Core / Domain（人体几何、长度统计、耦合求值/雅可比、损失与候选判定、低通、硬限速、纯安全谓词）
        ↓
Types / Contracts（`omnihand_o10_contracts` 纯运行时值对象）
```

- **纯核心判定标准**：导入并测试它不需要初始化 ROS、不需要模型安装空间、不需要网络或硬件。Pinocchio、NLopt、ament 资产查找属于 Adapter；数学公式、耦合系数的已解析表示和状态转换属于 Core/Application。
- wire schema（`rokoko_omnihand_msgs`）与模型资产（`omnihand_o10_model`）是构建期 ROSIDL/ament 产物，不进入运行时 import 层级栈。
- 安全关键控制采用**纯事件→纯效果**：Application 接收事件、返回效果，ROS runtime 是唯一 effects executor；事件/效果中不得出现 ROS Node/Publisher/Client/Future 或厂商对象。runtime 只有在外部发送成功后才回送成功事件推进"上一实际发送命令"。
- 自有运行代码固定为 Python 3 / `ament_python`（ADR-0009）；引入 C++ 须先修订 ADR 并补 include/CMake/link 门禁。
- 包内统一逻辑布局（按需创建，不预建空目录）：`contracts.py`（包内纯类型；跨包事实必须来自 `omnihand_o10_contracts`）、`core/`（纯计算）、`application/`（有状态编排）、`adapters/`（ROS/UDP/数值/资产）、`node.py`（薄 composition root，不保存第二份状态机）。

### 明确禁止的依赖边（及理由）

- `Core → rclpy/ROS 消息/launch`：纯计算不能依赖框架。
- `Core/Application → 厂商 SDK/CAN/USB`：硬件只能被最外层 Provider 遮蔽。
- `Application → adapters`：依赖倒置为 Port 或纯事件/效果。
- `omnihand_o10_control ↔ hand_retargeting` 互相 import：控制安全门不能读重定向内部状态；两模块只经 JointState wire contract 连接。
- `rokoko_hand_receiver → O10 各包`：Raw 边界不能知道机器人语义。
- `生产包 → rokoko_omnihand_system_test`：生产不能加载纯软件 Provider。
- `omnihand_o10_control → omnihand_o10_hardware_adapter`：控制只依赖 O10HardwarePort 纯事件/效果与 wire contract，生产 Provider 由 composition 选择。
- 任意受管包间循环；任意包 → `utils/common` 共享汇（禁止无法确定事实所有权的依赖汇）。

实际依赖 DAG 以各 `package.xml` 为准；`architecture_tests` 以测试形态强制上述规则（见第 6 节）。

## 4. 包布局（扁平化后现状）

仓库根即 workspace，`src/` 下 11 个 ROS 包平铺 + 一个被 `COLCON_IGNORE` 隔离的厂商前缀：

| 物理目录 | ROS 包 | 角色 |
| --- | --- | --- |
| `src/rokoko_hand_receiver_node/` | `rokoko_hand_receiver` | 业务节点 |
| `src/hand_retargeting_node/` | `hand_retargeting` | 业务节点（逐侧实例） |
| `src/omnihand_o10_control_node/` | `omnihand_o10_control` | 业务节点 |
| `src/omnihand_o10_hardware_provider_node/` | `omnihand_o10_hardware_adapter` | 设备 Adapter（不计为业务节点） |
| `src/rokoko_omnihand_launchpad_node/` | `rokoko_omnihand_launchpad` | 控制面进程（非业务节点） |
| `src/teleoperation_support/ros_interfaces/` | `rokoko_omnihand_msgs` | wire schema（.msg/.srv 单一来源） |
| `src/teleoperation_support/o10_contracts/` | `omnihand_o10_contracts` | 纯运行时值对象（关节名/索引/左右限位单一来源） |
| `src/teleoperation_support/o10_model_assets/` | `omnihand_o10_model` | URDF/MJCF/provenance 资产包（资产实体在仓库根 `omnihand_o10_model/`） |
| `src/teleoperation_support/production_bringup/` | `rokoko_omnihand_bringup` | 生产 launch/composition（`scripts/start_omnihand_control.sh` 为实现入口） |
| `src/teleoperation_support/system_tests/` | `rokoko_omnihand_system_test` | 纯软件 Provider、无真机 launch test（唯一允许的测试节点） |
| `src/teleoperation_support/architecture_tests/` | `rokoko_omnihand_architecture_test` | 架构门禁测试 |
| `src/third_party/agillink_omnihand_sdk/linux/x64/ros2/jazzy/` | （COLCON_IGNORE） | Agilink SDK 1.1.8 厂商安装前缀，非自有源码，不进依赖图 |

只有前三个提供业务节点；`teleoperation_support/` 不创建同名包、不提供跨包 import，不得演变成 `utils`/`common`。

## 5. Ports 与外部依赖映射

| 外部依赖 | 边界/Port | 单一 owner |
| --- | --- | --- |
| Rokoko UDP | Datagram ingress（`bytes + received_at`） | `rokoko_hand_receiver` Adapter |
| ROS 时间 | 各 ingress 显式生成不可变时间值（Raw 接收时间只由 receiver 创建） | 对应业务包 ROS runtime |
| 单调时钟 | `MonotonicClockPort.now()` | `omnihand_o10_control` Application |
| O10 运动学 | `FingerKinematicsPort`（FK + 完整平移雅可比） | `hand_retargeting` Application（Pinocchio Adapter） |
| 有界优化 | `FingerOptimizerPort`（有界单指候选 + 停止信息） | `hand_retargeting` Application（NLopt SLSQP Adapter） |
| 主动—被动耦合 | `CouplingModel` 纯值 + 求值/雅可比 Core API（非 Port） | `hand_retargeting` Core |
| O10 模型资产 | `ModelAssetProvider`（按逻辑侧取已验证 URDF/MJCF/provenance） | `hand_retargeting` Application（ament index Adapter） |
| O10 硬件 | `O10HardwarePort` 纯事件/效果 + wire contract | `omnihand_o10_control` Application；生产 Adapter / 纯软件 Provider 实现 |
| O10 触觉 | `O10TactilePort`（只读七区原始帧，不进控制安全） | `omnihand_o10_hardware_adapter` |
| 配置 | 每业务包不可变配置值对象（非共享 Port） | 对应业务包 Application |
| MCAP | 公开 Topic 观察边界，业务节点无 writer | 外部录制编排 |
| Launchpad HTTP/进程生命周期 | 本机控制面、单实例锁、子进程编排边界 | `rokoko_omnihand_launchpad` |

只有"生产 + 测试"两种真实实现用途才建 Port；普通纯函数不包接口。Port 不因当前 Adapter 缺能力而降级。

### 关键所有权（防第二份事实）

- 主动关节名称/索引/左右限位：`omnihand_o10_contracts`（唯一代码 owner）；
- `.msg/.srv` 定义与枚举数值：`rokoko_omnihand_msgs`（消费者不得复制 numeric literals）；
- 21 个 Rokoko 节点规范拼写：`rokoko_hand_receiver`（版本化官方 JSON fixture）；
- Raw 接收时间：receiver 在 UDP ingress 创建，下游只继承；
- 每侧长度窗口/冻结值/上一有效目标/恢复候选/平滑状态：`hand_retargeting` 对应侧 aggregate（左右不共享可变状态）；
- 每侧 `fault_latched`/新鲜度/限速基准/时间基准：`omnihand_o10_control` 对应侧 aggregate；`motion_enabled` 从自有状态派生只读。

## 6. 架构门禁（enforcement）

A01–A27 不变量（依赖 DAG 无环、core/application import 边界、控制无厂商依赖、生产排除测试 Provider、契约单一来源、资产不从绝对路径加载、Launchpad 只绑 `127.0.0.1:8710` 且不自动启业务节点、必需参数缺失即启动失败等）由 `rokoko_omnihand_architecture_tests` 以 `colcon test` 阻断执行，明细与测试名见 `src/teleoperation_support/architecture_tests/test/test_architecture_gates.py`——本文不复制清单。

仅两条**只能人工评审**：控制业务状态转换只发生在每侧 Application aggregate（A14）；运动使能/故障/IK/stale/限速业务状态不得出现在 Adapter、bringup、消息、资产和测试包（A21）。架构测试只证明"代码没长歪"，不验证 IK 精度、限速值正确性或故障时真的停发。

## 7. 未决问题（架构不静默回答）

1. **厂商无动作读取的内部实现**：wire contract 已定为逐侧 `ReadO10ActiveJoints` Service 并已交付；Provider 内部用 SDK 直读还是厂商扩展仍在演化，但不得改变 Service 语义或返回缓存。
2. **模型资产许可**：上游声明 Apache-2.0，但 `omnihand_o10_model/provenance.json` 的 `license_confirmed=false`；确认前不视为许可闭环。
3. **`joint_states` 物理语义**：独立测量还是命令回读未确认——跟踪误差不入安全判据，也不假设上游静默会触发硬件自动停止。
4. **Python 重定向性能余量**：需无真机 benchmark 证明双手可持续吞吐；跨语言迁移前先修订 ADR-0009 与门禁。
5. **安全与算法参数数值**：窗口、残差、优化、滤波、stale、恢复、轮询、超时、速度与时间额度均待真机标定；架构只强制显式配置与单位来源（A18：未标定参数必须是显式必需配置，不得伪装安全默认值）。
6. **真机 watchdog 与通信时序**：未验证，不得由代码结构推断。
