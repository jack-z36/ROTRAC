# ADR-0017：拇指专调保留为配置化的可选逐指调整

- 状态：Accepted
- 日期：2026-10-15
- 范围：`hand_retargeting` 中段算法、`RetargetingConfig`、per-hand 配置文件

## 背景

`session.py` 的 `_apply_thumb_adjustments`（thumb_roll/abad 增益与固定值）没有任何 spec 或 K03 算法基线条文依据，属真机调参产生的代码级事实；但参数来自 runs/ 会话的验证值，有真机有效性证据。删除会改变已验证的遥操作行为，原样保留则中段永含 O10 拇指专属补丁，票据 7.2 列为两可的 D4。

## 备选方案

1. **直接删除**：中段立即干净；代价是丢弃有真机证据的补偿，O10 遥操作行为退化且这次行为变更无 spec 授权，未来需要时要在无基线状态下重新调参。
2. **原样硬编码保留**：当前行为零风险；代价是"中段零 O10 痕迹"验收不可能达成，任何新手都被动继承 O10 拇指补丁，无成文依据的代码继续存活并随中段扩散。

## 裁定

保留但配置化：移入 `RetargetingConfig` 作为可选的逐指调整钩子（逐指增益与逐指固定值，缺省 None 表示不调整）；O10 配置文件携带现值并注明真机来源，新手不配置即无此行为。业界同型先例：dex-retargeting 的 `scaling_factor`、Drake SchunkWSG 的 `pid_gains`、LEAP teleop 模式对指 12/14 的固定补偿。

## 后果

- 中段代码恢复手无关，经验补偿从代码事实变为显式配置（对齐 A18"未标定数值显式配置、不伪装安全默认"的精神）。
- 代价：配置面增加，逐指元组可配错，加载期必须校验元组长度与指数一致。
- 风险：补偿脱离代码后，配置丢失或误删会让 O10 行为静默退化，O10 配置中必须保留来源注释；"经验值无算法基线条文"的债务并未消失，下次真机验证时应考虑把它升格进 K03。
