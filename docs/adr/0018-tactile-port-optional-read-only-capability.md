# ADR-0018：触觉 Port 保留为只读可选能力

- 状态：Accepted
- 日期：2026-10-15
- 范围：HandAdapter Port 能力表、触觉 wire 契约、硬件 Provider 实现义务

## 背景

`O10TactilePort` 与触觉 wire（1×268 mono16 七区表）是 Agilink O10 厂商专属契约；而"触觉只读、不进控制安全、启动不自动读取"是 Port 表中值得沉淀为通用原则的纪律。新手可能根本没有触觉，或阵列布局完全不同，票据 7.2 列为两可的 D5：保留、泛化为强制感知 Port、还是随 O10 一并移除。

## 备选方案

1. **随 O10 一并移除触觉能力**：实现面最小；代价是现有只读观测面（七区可视化、录制）消失，"只读不进安全"原则失去载体，未来新手需要触觉时要在没有先例的情况下重新设计。
2. **强制所有 HandAdapter 实现通用触觉 Port**：接口统一；代价是无触觉的手被迫 stub 或伪造实现，统一布局无法覆盖差异巨大的传感阵列，违背"不伪装能力"的保守立场。

## 裁定

触觉 Port 保留为可选能力：Port 契约与"只读、不进控制安全、启动不自动读取"三项纪律通用化进 Port 能力表；具体实现可选，无触觉的 HandAdapter 对触觉读取返回 `NOT_SUPPORTED` 响应码；O10 实现保留现有七区契约不动。

## 后果

- 新手最小实现面不被迫膨胀，触觉安全边界（永不进安全）成文保留。
- 代价：控制层与下游必须显式处理 `NOT_SUPPORTED`——能力缺失既不能当健康也不能当故障，诊断与面板需要第三种表达。
- 风险：可选能力引入"哪些 Port 必须实现"的灰区，Port 能力表必须逐能力标注必需/可选；`NOT_SUPPORTED` 若被滥用为"暂时不可用"会污染故障语义，其响应码语义需要成文约束。
