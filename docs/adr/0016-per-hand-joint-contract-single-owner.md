# ADR-0016：关节契约按手单 owner 落在 per-hand contracts 包或配置

- 状态：Accepted
- 日期：2026-10-15
- 范围：A11 门禁、`omnihand_o10_contracts`、per-hand contracts 包与配置文件

## 背景

A11 的机制——任何手的主动关节事实必须恰好有一个代码 owner（ENFORCED）——手无关；其内容（10 关节名与左右限位，`joints.py`）是 O10 专属。ARCH ownership 表把"固定主动关节语义"锚定在 `omnihand_o10_contracts` 行下，门禁测试按现包名锚定。新手关节事实必须有落点，而 A11 文本只约束唯一性不约束包名，票据 7.2 列为两可的 D3。

## 备选方案

1. **所有手的事实都写进 `omnihand_o10_contracts`**：门禁与 DAG 零改动；代价是 O10 命名的包持有其他手的事实，包名与内容语义漂移，跨手事实在同一包内互相纠缠，A11 的断言对象失焦。
2. **泛化为单一 `hand_contracts` 包加运行时注册表**：表面统一；代价是注册表成为共享依赖汇（A17 精神违反），唯一 owner 语义被注册表稀释，门禁只能断言注册表自身而无法逐手断言事实归属。

## 裁定

1. 保留包名语义并按手切分：`omnihand_o10_contracts` 继续专属 O10；新手的关节事实建 `{hand_id}_contracts` 包，或在数据驱动 HandProfile 下由该手配置文件承载，加载校验后生成 JointContract。
2. A11 门禁改写为逐手断言："每只手的主动关节事实必须恰好有一个代码/配置 owner"，不再锚定单一包名；ARCH ownership 表同步改写。

## 后果

- 每手事实独立演进、语义清晰，门禁逐手可断言；换手不触碰 O10 契约包。
- 代价：每手多一个 contracts 包或配置文件，结构存在轻微重复；A11 测试与 ownership 表必须与第一次换手同步改写，否则门禁仍锚定旧包名。
- 风险：配置化契约把 YAML 笔误变成运行期安全事故，加载期必须强校验（名称数、维度、左右限位数目一致）；配置文件从此是安全关键资产，必须纳入版本控制与门禁扫描。
