# ADR-0019：诊断消息继承结构骨架、O10 专属字段按手参数化

- 状态：Accepted
- 日期：2026-10-15
- 范围：RetargetingState 与控制状态诊断 wire、K05/K06 类接口契约、`ros_interfaces`

## 背景

RetargetingState 的逐指残差与求解器停止原因、控制状态的厂商错误位掩码（bit0–4）都是 O10/Agilink 专属内容；但消息结构骨架——逐侧、事件驱动、只读、availability/NaN 约定、绝不反向驱动控制（Spec D52–53、K05/K06）——是必须继承的通用纪律。字段是否随手参数化涉及 wire schema 兼容，票据 7.2 列为两可的 D6。

## 备选方案

1. **字段冻结，所有手共用 O10 形状**：wire 零演进；代价是新手的诊断被迫塞进语义不符的字段——别人的残差、别人的错误位，消息名与内容不一致，K06 的字段级含义作废，跨手数据不可比。
2. **完全动态诊断载荷**（无类型 key-value/JSON）：一次到位的灵活；代价是丧失类型化 wire 契约与 A16 单一来源，Launchpad 曲线、录制与回放失去可渲染的类型化字段，NaN/availability 约定失去结构强制。

## 裁定

字段级参数化：诊断消息的结构骨架（逐侧身份、事件驱动、只读、时间戳语义、availability 约定）跨手固定；O10 专属字段（残差、求解器、错误位掩码）的维度与语义按手在接口包与 HandProfile 中声明，A16 单一来源按手保持；骨架字段（side、header、availability）不得随手改名，其稳定性由门禁断言。

## 后果

- 每手诊断语义真实，结构纪律统一，工具层不必 per-hand 分叉。
- 代价：每只手带来一次 wire schema 新增或修订，K05/K06 类契约文档与门禁必须同步；跨手聚合视图需要一层字段映射。
- 风险："字段级"的边界若守不住就会滑向动态载荷——骨架字段与可参数化字段的划分必须落进门禁，而不是停留在约定；本 ADR 只固定划分原则，具体骨架字段清单由首次换手时的接口包修订钉死。
