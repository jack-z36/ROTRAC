# 文档撰写规则（doc-writing）

本仓库文档体系按"稳定知识 / 在途工作 / 冻结历史"三层组织，入口在 `AGENTS.md`。本文件是所有 `.md` 写入的落点权威。写错位置会被写入门禁 hook 拦截，漏网的会被 `scripts/doc_gate.sh` 在关票时抓到。

## 写任何 .md 前的四问（按序判定，命中即停）

1. **能不写吗？** —— grep 代码/配置/测试就能得到的（话题表、接口签名、包结构清单）→ **不写**，环境是事实源，抄进文档只是多一份会过期的拷贝；复述已有文档的 → **不写**，去改那一份。
2. **是决策还是词？** —— 难逆转 + 反直觉 + 真权衡的裁定 → `docs/adr/`（编号递增）；术语与口径 → `CONTEXT.md`（唯一词汇表）；review 期规则 → `CODING_STANDARDS.md`。
3. **是贵再生的稳定知识吗？** —— 新会话重推导成本高的内容（字段语义/单位/坐标系、踩坑结论、算法基线数字、硬件前置、安全红线）→ `docs/` 平铺，中文文件名，正文开头写一行"新会话为何需要本文"。
4. **是过程还是现状？** —— 在途工作 → `.scratch/<feature>/` 票据（一票一文件，`Blocked by` 声明依赖）；一次性叙事或会话交接 → **不进仓库**（临时目录）；现状结论（能力基线/在途/已知问题）→ `STATUS.md` 对应节。

判定口诀：代码有的是事实，文档只存代码看不出来的贵知识；过程进票据，结论进 STATUS，叙事进归档。

## 硬拦截清单（写入门禁 deny，无歧义才拦）

- 仓库根新建 `.md`，白名单之外。白名单：`AGENTS.md`、`CLAUDE.md`、`README.md`、`STATUS.md`、`CONTEXT.md`、`CODING_STANDARDS.md`
- `docs/` 内新建子目录或向 `adr/`、`agents/` 之外的子结构写文件（扁平纪律；新建结构是架构决策，必须先开票评审）
- 用 Write/Edit 修改 `archive/` 内任何文件（冻结历史；归档动作走 `git mv` + `archive/INDEX.md` 登记，不经过文本写入）
- 修改 `docs/agents/` 三件套（tracker / triage / domain 是体系配置，变更走专门票据）

`src/` 包内 `.md` 不拦（包级 README 属合法形态）；`skills/` 内本文件及同类规则文档合法。

## 知识公理（准入判据）

知识文档的存在理由是**穿越上下文窗口边界**。准入判据 = 新会话的再生成本：便宜可再生（grep 即得）不写；贵再生（深读全库 / 跑实验 / 踩坑）必写。每份 `docs/` 文档必须能回答"一个新会话为什么需要我"。

## 蒸馏与归档惯例（关票硬步骤）

票据关闭 ≠ 代码完成。关票必须完成蒸馏，漏蒸馏按 diff 缺陷报：

- 贵再生知识 → `docs/`（过上面的四问）
- 决策 → ADR；术语 → CONTEXT.md；现状结论 → STATUS.md
- 叙事与被取代文档 → `git mv` 进 `archive/<单位>/` 并在 `archive/INDEX.md` 登记
- 关票验收：`scripts/doc_gate.sh` 全绿（error 清零；warning 记录进关票回复）

## 语义审计（自然锚点触发）

`/retro` 会话时、用户点名"文档体检"时、spec 级实施完成后必检：派子代理对照代码逐份核验 `docs/` 与 `STATUS.md`，git log 找"代码改了但文档没动"的漂移对；产出修复票（`.scratch/doc-audit/`），并在核验过的文档导语更新"最近核验：日期"。
