## Question

决定 max_joint_rates、smooth_time_constants 等配置参数的统一收口位置，回答票据 07 的问题 4。

**当前散乱现状**（据票据 07）：
- shell 脚本中的命令行参数
- 两份 launchpad yaml（default.yaml + diagnostic.yaml）
- 可能还有代码中的硬编码默认值

**必须决策**：
1. **统一收口到哪里**？
   - 选项 A：全部收敛到 HandProfile 配置文件（每只手一份 YAML）
   - 选项 B：分层配置（HandProfile 管手特定参数，launchpad yaml 管运行时参数）
   - 选项 C：统一到 launchpad yaml，HandProfile 只提供「必需的手硬件参数」

2. **配置覆盖的优先级**：
   - 如果采用分层配置，当 shell 参数、yaml、HandProfile 都提供同一参数时，谁覆盖谁？
   - 是否需要显式的「配置合并策略」？

3. **配置的版本控制与分发**：
   - HandProfile 配置是否随代码一起 git 管理？
   - 还是作为「手硬件描述资产」独立管理（类似 URDF）？

4. **与现有 launchpad 机制的兼容**：
   - default.yaml vs diagnostic.yaml 的差异是否保留？
   - 还是统一为一份配置 + 运行时模式切换？

**产出**：Resolution 记录配置收口方案 + 配置文件结构草案（哪些参数在哪个文件、优先级规则、示例配置片段）。
