## Question

汇总前序所有决策，产出完整的「换手清单雏形」与「接口签名草案」，作为票据 08/09 写正式 spec 的直接输入。

**产出 1：换手清单**（`artifacts/hand-replacement-checklist.md`）

清单包含三列：
1. **必改项**：换手必须修改的模块/文件/配置
   - 例：`hand_profiles/o10_profile.yaml` → `hand_profiles/new_hand_profile.yaml`
   - 例：`backends/o10_backend.py` → `backends/new_hand_backend.py`
   - 例：URDF/MJCF 模型资产

2. **可选改项**：可能需要调整的参数/配置
   - 例：IK 参数、平滑常数（如果新手特性差异大）

3. **不改项**：换手完全不动的模块
   - 例：手套侧 receiver 全包
   - 例：中段归一化/IK/平滑核心逻辑

**产出 2：接口签名草案**（`artifacts/interface-signatures.md`）

每个适配层的完整接口定义：
1. **手套侧**：`RawHandFrame` 消息定义（字段、类型、单位、坐标系）
2. **手侧**：`HandAdapter` Protocol（`send_target` / `get_feedback` 签名 + 错误类型）
3. **HandProfile**：配置结构（YAML schema 或 Python dataclass）
4. **中段接口**（如果需要显式定义）：归一化/IK/平滑的输入输出类型

每个接口包含：
- 方法/字段签名
- 参数语义说明
- 错误处理约定
- 示例用法（伪代码）
